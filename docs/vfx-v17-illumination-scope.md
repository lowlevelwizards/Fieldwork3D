# V17 — Muzzle, detonation and illumination
Base dc61b990a9442bfa43214dd8cba779d08dea5b41 (V16 merged). This is a presentation-only roadmap, not a claim that V17 was previously approved in code.
## Audit and boundaries
- The actor owns one muzzle mesh, currently a transparent octahedron; the sidearm reuses it at the actual solved socket but reparents it to actor root. Shot-age and visibility come from existing shot history. The 2D cue remains authoritative for presentation; no firing changes.
- V7 light presenter uses two fixed shadowless PointLights (muzzle 24 units/.09s, flash 58 units/.24s). It picks the strongest eligible event with stable ID tie-break. No wall occlusion: global scene illumination can cross solid architecture. The muzzle light strength currently receives an already-decayed, clamped mesh scale.
- Grenades and detonation spheres are managed in the combat effects presenter; flash expands 5+70*age and fades over .7s, with per-pooled-mesh material. Existing smoke, flash records and effect disclosure are independent. Personal replay currently suppresses global transient evidence.
- Existing optical blocker builder, session-owned geometry, weapon-light rays and W5 opaque wall/fog ownership are reusable. Do not change AI illumination, visibility, damage, grenade behavior, weapon timing, audio or simulation authority.

## Checkpoint V17.3a — conservative light sphere containment
After strongest disclosed muzzle/flash selection, clip each active shadowless light's distance to the nearest opaque wall, actual optical door leaf or high-cover boundary, with a visual wall shell. Uses existing per-session spatial queries, no extra geometry index, no per-candidate geometry work, no idle wall queries. Never set Three.js light distance to zero (unlimited); suppress a source within a blocking shell. Clear range on every frame/reset. This is intentionally isotropic and can under-light an open side near a wall; directional receiver extension through openings and browser validation remain explicitly open. No changes to gameplay light field or fog.

## Checkpoint V17.3b — directional reach mask
Adds a reusable 64-sector CPU mask for directional receiver illumination. Each bin conservatively covers a thickness-expanded angular interval, so short segments and jambs cannot disappear between center rays. Uses local session wall/cover queries and actual optical door leaves; at most 96 admitted blocker segments per source, fail closed on overflow or invalid/embedded source. Tests cover open direction, real aperture, wraparound, narrow blockers, doors, cover and repeatability. This is a geometry prerequisite, not yet connected to GPU receivers; the production radial containment remains active. No extra render cost yet. Receiver shader integration and acceptance remain open.
