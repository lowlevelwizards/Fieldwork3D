# WC0 — Window coverings audit and implementation contract

Baseline: main commit 553b2f13e8906df9d0f86eb61a75e63e7b614590 (2026-11-26). Source inspection, not browser acceptance or executed tests. No runtime changes in WC0.

## Existing ownership and findings
- `src/breach-site.ts`: WindowOpening holds id, position, width, orientation, sill/head, interior flag, glazing style and optional treatment. Treatment enum is none/open-curtains/bars/boarded. No dedicated covering state.
- `src/breach-windows.ts`: exterior apertures chosen by functional room and facade; interior glazing appended; WindowState independently owns open, integrity, shattered, operable. Preserve these pane semantics.
- `src/worldgen/interior-glazing.ts`: only useful room pairs, avoids private uses; some full-height partitions. Do not blanket-cover public interior glass.
- `src/worldgen/window-geometry-contract.ts` and `window-collider-sync.ts`: authoritative pane segment, sill/glass footprint and exactly-one structural barrier; covering geometry must not alter this contract.
- `src/breach-archetypes.ts` applies dressWindowSecurity after functional furnishing and wall dressing, before final synchronization and fortification. `src/worldgen/window-security.ts` uses a seeded sequential roll and building archetype (neglected/vacant boards, industrial bars, residential open curtains). No room-specific privacy or side attachment. Boarded openings add a softwood high obstacle; repeated invocation currently appends boards without removing previous ones. Preserve existing board behavior, make migration idempotent.
- `src/rendering/breach-site-openings-builder.ts`: static tied-open fabric boxes on one local face, fixed color; bars also fixed face; glass has own registered mesh. Local group follows aperture orientation. Need proper signed room-facing side, offset outside frame/glass, dedicated registered dynamic visual group, no duplicated legacy curtain meshes.
- Existing rolling shutters are door-kind shutters, not dedicated window shutters. Do not replace or alias door IDs, door travel, locking or movement code.
- `src/breach-game.ts`: unobstructed uses wall, door and indexed optical cover; actor-pair geometricallyVisible uses combat exposure with effective eye/aim height and revision cache. `src/breach-optical-occlusion.ts` and `breach-vision-polygon.ts` build optical segments; `equipment-weapon-light-beam.ts` and `equipment-light-field.ts` consume optical blockers. Integrate all relevant consumers; do not simply insert soft coverings into coverState or walls (would conflate sight, collision, and ballistic protection). Review civilian and enemy observers, 2D/3D fog and historical presentation.
- `src/breach-world-context.ts`: session-owned indexed physical geometry with revision invalidation; keep soft optical geometry independent. `breach-fog-cache.ts` and `equipment-sight-lighting.ts` depend on objectRevision; use event-driven invalidation including replay restores. Distinct sessions must not share mutable state.
- `src/breach-replay.ts`: window snapshots are shallow copied and shared while objectRevision unchanged; `breach-replay-window-knowledge.ts` records only observed open/shattered transitions. Extend snapshot/observation contracts, retain older replay compatibility and avoid hidden-state leaks. Prefer immutable flat scalar values or explicit deep copies.
- `src/breach-window-bash.ts`: bash rejects boarded panes and exempts matching window barrier; covering and pane actions must be distinct. Review traversal/deployment and contextual orders before hard shutter enablement. Existing pane ballistic resolution, glass impact and acoustics remain independent.
- `src/asset-lab-main.ts` builds window specimens; reuse lab pipeline. Existing tests include map-14-window-security, map-11-window-styles, map-12-window-gallery, architecture-02-interior-glazing, architecture-04-full-height-glazing, package-c6-world-geometry-contract, lw-windows, ei4-window-bash, visibility-03-optics, breach-fog-ray-broadphase-performance. Legacy enum assertions require intentional compatibility update.

## Contract and decisions
Use one optional covering descriptor per aperture for WC1, independent from glass state and legacy security treatment. Six families: fabric curtains, vertical slat blinds, horizontal blinds, roller shade, hinged shutter, rolling security shutter. Preserve bars/boards as existing security treatments. Legacy open-curtains normalize to open curtain on read; never show two curtain sets. Use stable window ID, side (+/- normal), family/material palette, quantized opening and optional slat tilt, integrity and lock only when meaningful. Keep seed-authored initial state immutable; runtime changes in session-owned state. No geometry or dynamic visibility for uncovered windows. Multiple stacked coverings deferred.
Open/partial/mostly closed/closed; blinds additionally support coarse tilted state where appropriate. Define explicit aperture-local optical coverage versus physical barrier and visual geometry. Partial vertical openings use coarse intervals; horizontal raised/tilted coverage is height-aware for actor sight, with documented conservative top-down approximation rather than many tiny slat rays. Ordinary fabric/shades/blinds conceal, not ballistic cover or navigation blockers. Hard shutters follow material and state; block traversal only where physically appropriate, without duplicating sill/glass collider. Independent pane/cover damage and state. Decorative fixed exterior shutters distinct from functional ones.
Art: broad folds, few chunky slats, graphic texture bands, simple oversized rods/headrails, muted room-coherent palette, no cloth physics or per-slat simulation, no micro bevels. Reuse shared geometry/materials; static batching where safe, update only changed covering group. Validate both orientations and interior/exterior faces, full-height and low sill, no z-fighting, no hidden-state leakage.

## Stage gates
WC1: descriptor + state normalization, geometry contract, six procedural visual families, shared asset lab specimens (open/partial/closed, both orientations). Preserve current world generation output until WC2; test legacy normalization, dimensions, no mutation/duplication and deterministic visual output.
WC2: deterministic placement keyed by seed and stable window/room identity, interior-side resolution after room orientation, occupancy + role + opening suitability; residential curtains/horizontal blinds, offices vertical/horizontal/shades, clinics selective shades, industrial selective exterior shutters, storefront security only when justified. Keep public shopfront and clerestory often uncovered. Do not displace doors/furniture or change structural aperture. Audit generation across archetypes, seeds, both orientations, old maps and no repeated boards. Keep hard shutter gameplay disabled until complete.
WC3: shared optical query for actor/civilian/AI sight, ground visibility, 2D/3D fog and light; partial coverage, height-aware where supported. Cache by session/revision, invalidate only on meaningful change. Separate true optical blocker from physical cover; preserve concealment vs protection. Replay knowledge/snapshot compatibility and no omniscient fog presentation. Tests: symmetry, opening, crouch/stand, memory/seek, cache invalidation, visibility parity.
WC4: contextual open/close and appropriate slat adjustment, accessible side/reach and blocked/locked validation, simple animation, independent pane actions, cancel/replay; no per-frame full-map scan.
WC5: damage/destroy independent of glazing, material-aware hard shutters, traversal/deployment checks, AI respects shared observation geometry, limited state interactions if justified. No automatic blind fire or perfect knowledge. No changes to existing shutter doors. Verify physical/optical/ballistic separation and destruction, bars/boards regression.
WC6: bounded seed and scene acceptance, browser capture of all families plus actual maps, performance comparison for draw calls and sight/cache costs, replay restore, critical CI, release only after compatibility with concurrent environmental/AI changes and successful prior deployment. No stage should claim runtime verification without executed evidence.

WC0 exit: source ownership and migration plan documented; no tests executed because no runtime changes; runtime baseline, visual verification and consumer completeness remain WC1–WC6 gates.
