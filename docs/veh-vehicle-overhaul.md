## Checkpoint 2 — shared rendering
All six family dimensions enter the canonical asset catalogue and Asset Lab inventory. The common renderer now uses one vertex-coloured opaque mesh; the site scene acquires geometry via the existing leased template library, with one lazily allocated site-owned material. This keeps owner visibility/collapse transforms and the existing repeated fixture batch collector. No procedural placement enabled. Dedicated Vehicle Lab, visual validation and measured performance remain pending. Historical legacy geometry branches are temporarily retained until source-contract tests are deliberately replaced.

## Checkpoint 3 — shadow placement
Added deterministic parking-only candidate planner with diagnostics, canonical rotated dimensions, vacant capacity, reserved bay, sidewalk/curb, road, entry and door reserves, protected encounter points and existing cover rejection. No map mutation or production enablement yet. Real lot eligibility needs measurement; garage/driveway/loading topology and vehicle-height integration are still pending. Existing generated wheel stops may reduce shadow acceptance because the final planner needs to run before wheel-stop allocation.

## Checkpoint 4 — dedicated lab and diagnostics
Vehicle Lab is a Vite entry linked from both developer menus. Uses the same leased vehicle mesh, supports family/configuration/paint/condition, 5 camera views, family lineup, 1/5/10/20/50 repeat stress preview, cached vs instanced comparison and canonical footprint. It has isolated lighting, not a substitute for tactical scene captures. Added 44-site shadow parking manifest via the targeted workflow. Corrected scene material tracking to preserve the concrete material type. Visual browser acceptance and real-site placement remain pending.

## Checkpoint 5 — surface identity and lifecycle
All families now use existing sheet-metal physical material and metal visual substrate rather than the legacy softwood fallback. Added prominent van identity panels, medical symbol, municipal cargo stripe, SUV rack and additional fleet/taxi/aid stripes in the same compiled mesh. Lab resize cleanup is explicit. Fine texture atlas, exact tactical cover profile and human art review still pending; do not enable placement before measured eligibility and critical movement tests.

## Checkpoint 6 — shared parking row topology (shadow)
Added optional serialized vehicleParking plan on exterior zones, with parallel/perpendicular bay orientation, private street/sidewalk clipping and a 48-unit reserved circulation aisle. Both markings and candidate dimensions use the same row geometry; existing snapshots have no new metadata and keep their old layout. A marked modern driveway or parking zone can use a wider curb cut. New layouts remain shadow-only pending actual generation coverage, accessibility sign/transfer planning, and mobility validation. Audit now compares legacy and proposed layout on the same seeds. No forced map expansion or car downsizing.

## Checkpoint 7 — opt-in generation integration
Added explicit generateSite generationOptions.vehiclePlacement pilot, default false. Modern forecourts are attempted only for compatible public/industrial properties, reverted to original if too shallow. Existing props/landscaping cannot consume the row or aisle; old parking stops/signs are not authored in new modern rows. Final vehicles append after encounter planning and pass existing synchronous navigation validation, failing closed to an empty marked lot. Fixed-seed audit now compares actual opt-in sites as well as shadows. Residential driveways, loading-specific plans, actual population coverage, accessibility and production enablement remain open; no historical site rewrite.
