User requested complete removal of old generic placeholder artwork and the old four-class weapon system. Treat this as a release-critical cross-system migration, not just an art-stage palette change.

Use the existing Arsenal catalog and validated configured recipe as the identity authority. Migrate class-only saved equipment at the read boundary to a deterministic authored reference, preserving owned-object identifiers, valid selections and replay compatibility. Keep old identifiers only as narrowly scoped input migration data until supported historical saves have migrated. Do not introduce new behavior or weapon performance changes.
## R4: migrate dependent systems
Convert creation/selection, ownership and save readers, campaign/Quick Play, faction issuance, replay and labs to the catalog identity; derive existing game behavior from the existing data during transition. Replace old generic equipment entries and class-only selection surfaces. Verify migration on actual save fixtures before removing old types and lookup tables.
## R5: remove obsolete APIs and residual references
Delete remaining unused legacy implementation and obsolete diagnostics/tests; keep historical Git commits intact. Search active source, scripts, tests and UI for obsolete identifiers and confirm no runtime paths remain. A narrowly scoped compatibility reader may still recognize historical serialized strings if retaining historical saves; explicitly disclose this exception rather than claiming literal zero references. If full zero-reference removal conflicts with legacy save compatibility, resolve at final acceptance.
