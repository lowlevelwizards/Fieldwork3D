## W2.0 — Reference and invariants

Actual W1 browser evidence, 90 live frames per seed/viewport:
- Mobile seeds 23/97: 973/1330 p95 total draws, 393/514 p95 materials, scene p95 51.2/55.0 ms.
- Desktop: 972/1330 draws, 392/515 materials, scene p95 61.1/74.0 ms.
- Whole-wall weathering: 68/88 real transparent submissions per frame on each viewport (mean 78 across these seeds; 34/44 visible wall bodies with two transparent passes). W1 confirmed 21 -> 0 depth-state mismatches on both viewports.
- Evidence is software WebGL CPU/driver timing, not physical GPU or mobile FPS. Capture exact W1 base again alongside W2. No performance claim from counts alone.

Current source: buildGeneratedSite clones the shared pixel-pattern MeshStandardMaterial, creates a bounded deterministic RGBA mask (64–256 x 64, mipmapped), an independent double-sided MeshBasicMaterial and two-quad child per conditioned wall. Texture and material ownership are site-local, mask preview updates image.data in place. The two transparent passes are a measured cost, not the old one-draw comment. The overlay is unlit and sorts independently; W1 opacity scales it separately. Existing base material already uses ageMaterialColor and metric repeating UVs from mapBoxPixelUV. Do not replace that texture with a stretched one or mutate any shared palette/cache geometry. The mask's row convention is top-to-bottom, old overlay uses bottom-zero UV with DataTexture flipY false: verify orientation, do not silently perpetuate inverted runoff. W1 leaves facade groups at order 1001, fog at 1000, independent detail at 1002.

## W2.1 — One integrated surface path

- Add a render-only wall surface helper; pilot behind explicit ?wallWear=integrated (legacy default until acceptance, ?wallWear=legacy rollback). New path uses the existing body MeshStandardMaterial with the existing shared pixel base map plus one site-owned RGBA condition mask sampled within the same fragment program; eliminate the extra child geometry/material entirely. Choose shader integration instead of generating full unique albedo textures: preserves authored base tile detail, UVs, mip levels, existing material lighting, and bounded mask memory. A texture-compositing alternative is allowed only with measured equivalent or better cost and fidelity; document decision.
- Use normalized local wall coordinates independent of repeating base UVs. Prefer existing local position/normal with per-material immutable extent uniform; no per-wall geometry clones or attributes. Orient front/rear consistently, mask only broad faces, exclude thin edges/cap/skirting, clamp sample to mask footprint, explicitly map world height to top-down mask rows. Keep existing same mask on both sides in W2; separate interior/exterior art is W3. Avoid texture transform mutations and new per-frame work.
- Mix condition color into lit diffuse/albedo in linear color space using alpha coverage, leave structural alpha and depth independent. Preserve tint/contrast and material texture readability; avoid double darkening from the ageMaterialColor step. Weathering responds to lighting rather than appearing like a translucent film, including shadows and night/flashlight. New appearance intentional, exact pixel parity is not required; no unintended changes outside wall bodies. Keep shader hook composition with world graphic lighting (onBeforeCompile and stable customProgramCacheKey, no per-wall shader variants). Verify legacy lighting opt-out, default graphic lighting, transparent facade/cutaway variant and shadow caster. No emissive unlit workaround, no alpha discard for patina.
- Integrate only for generated wall bodies with a condition mask. No weathering overlay, standalone weather material, extra shadow submission or independent disclosure object in integrated mode. Preserve body geometry, base material, wall cap joints, skirting, local surface wear decals, openings, glass, collision, room/floor weathering and all VFX. Clean walls remain clean; no extra texture allocation on zero condition during normal gameplay. Legacy fallback map unchanged.

## W2.2 — Lifecycle, Map Lab and consolidation

- Reuse conditionWallPixels, wallPatinaDimensions and the renderer-owned sitePatinaTextures/patinaWallSurfaces. Do not add a second weathering generator or parallel texture registry. A single mask per conditioned segment, bounded width/height and explicit RGBA8+ mip budget, no duplicate base map, no render targets. Dispose each unique mask exactly once on site swap; retain shared base maps and shared geometry. No per-frame mask generation or texture uploads.
- Existing Map Lab condition slider keeps its rAF coalescing and deferred rebuild. For a site with an allocated mask, 0–100–0 updates existing buffer; preserve clear alpha at level zero and deterministic regeneration. If initial clean site has no mask, either bounded Map Lab-only eager allocation or deferred rebuild on first nonzero condition (document behavior and verify). No gameplay allocation on clean walls just for slider. Ensure repeated changes never create extra geometry/programs/textures. Old overlay-specific material updates stay only in rollback path; remove obsolete production references after promotion, keeping minimal rollback if needed.
- Retain W1 wallOwners and applyWallMaterialState, known-exterior/opacity/depthWrite/order policy. A cutaway scales the already-integrated surface via the wall's single alpha; no separate patina opacity on the new path. No fake transparency for weathering, no new visibility checks or knowledge mutation. W5 will reconstruct foreground facade/fog ordering; W2 deliberately leaves that policy intact.
- Existing local wall damage and wear, bullet/blood effects and VFX suite remain independent. W2 does not bake dynamic evidence or modify doors, glass, roof, floors, materials on unrelated objects, collision, worldgen semantics or AI.
